# 项目文档导航与维护规范

本项目文档体系按内容的生命周期、变动频率与职责边界进行划分。除项目根目录下的 [README.md](../README.md)（项目门面介绍）和 [CHANGELOG.md](../CHANGELOG.md)（版本变更与发版记录）外，`docs/` 目录下的内容按以下规范归档与维护：

## 1. architecture/（全局架构现状）
承载系统当前已落地的全局架构状态，属于随代码同步更新的**活文档**。遵循**单一事实源（Single Home of Facts）**原则：不维护多余的目录索引文件，每项架构事实在整个仓库中只在此处定义一次，其他文档仅通过链接引用，核心断言需直接指向真实源码路径。

架构文档采用**“`overview.md` 轻量化基座 + 按需平铺专题文件”**的组织形式，图表统一使用 **Mermaid** 绘制：
- **`overview.md`（固定只写两张 Mermaid 图 + 一组约束，不堆砌细节）**：
  1. **模块边界与源码地图**：用 Mermaid `flowchart` 画出系统核心模块划分、外部依赖与调用方向，并标明各模块对应的源码目录或入口文件。
  2. **核心执行链路与数据流**：用 Mermaid `sequenceDiagram`（或 `flowchart`）画出核心请求/数据从输入、处理到落盘/输出的完整路径，并指明关键数据结构在源码中的定义位置。
  3. **系统不变量与边界约束**：列出不可违反的状态机规则、并发/事务边界或协议硬约束。
- **平铺专题文件（`<topic>.md`，按需新增）**：除上述全局主干外的具体子系统或领域细节，不在 `overview.md` 内无限追加，而是直接在 `docs/architecture/` 下按需平铺新建独立的 `.md` 专题文件（不做编号与固定章节限制）。

## 2. spec/（按 Issue 归档的功能设计与改动记录）
作为功能需求、架构改造提案与执行过程的增量归档库，严格执行**只追加、不删除历史记录**的策略：
- **按需与 GitHub Issue 关联（`issue#<N>/`，编号无需连续）**：当维护者发起需要设计方案或架构改动的任务时，以对应的 GitHub Issue 编号建立独立文件夹，命名格式为 `docs/spec/issue#<N>/`（例如 `docs/spec/issue#1/`、`docs/spec/issue#15/`）。并非云端每个 Issue 都需要在仓库内建立文件夹，目录编号自然呈稀疏分布。
- **内部结构自包含且灵活**：每个 `issue#<N>/` 文件夹作为单次改动的自包含上下文容器，内部可自由组织文件结构（如 `spec.md`、分册设计、实施 Checklist、UI 矩阵、原型图或验证快照）。主文档开头需注明对应的 Issue 链接及本次改动影响的 `docs/architecture/` 模块。

## 3. adr/（架构决策记录）
专门记录架构设计与关键技术选型的演进链路及权衡过程。文档采用四位数递增编号命名（格式为 `0001-decision-title.md`），遵循不直接覆盖原决策的原则。当既有决策在后续实践中被推翻时，按以下三步处理（可通过 `harness adr supersede <old-id> <new-slug>` 自动完成）：
1. 新建一篇更高编号的 ADR 文档，阐述新的技术方案、上下文及替代关系（注明取代了哪篇旧 ADR）。
2. 在旧 ADR 文档的顶部元数据中，将状态更新为已被取代（例如标记为 `Superseded by [ADR-0012](../0012-xxx.md)`），并在文档底部追加一段失效说明，如实记录原方案在实际落地中遇到的问题或不再适用的原因，以此沉淀踩坑经验。
3. 将更新完状态的旧文档移入 `adr/superseded/` 子目录中归档，保持 `adr/` 外层主目录永远只展示当前依然生效的架构原则。

## 4. runbooks/（部署与运维操作手册）
聚焦于系统的实际交付、运行与维护操作。这里存放开发环境搭建指南、生产环境变量说明、CI/CD 流水线构建步骤、数据库迁移操作规程以及线上常见故障的排查与恢复手册，指导开发者和运维人员如何安全、标准地将代码运行和维护起来。

## 5. reference/（外部参考与调研沉淀）
用于存放第三方接口规范、行业标准等原始外部资料，以及经过提炼总结后的技术调研文档。
- **定稿落库即封存**：无论是外部文件还是调研总结文档，一旦合入仓库即视为静态基线，后续不再直接修改（若有新结论应作为新文件补充）。
- **三列索引登记（[INDEX.md](reference/INDEX.md)）**：目录根部维护 `INDEX.md` 索引文件，仅保留 **文件路径**、**来源链接 / 背景说明**、**备注** 三列。每次新增参考资料时必须同步登记。
